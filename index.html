01 · IA / RAG 2026

LocalArabi_RAG

Chatbot de questions-réponses en arabe sur des documents PDF et EPUB. Chaque réponse cite son fichier, sa page et son intervalle de lignes — et rien ne quitte la machine.

  • Citations vérifiables — fichier, page imprimée et lignes, pour retrouver le passage dans l’exemplaire du lecteur.
  • Récupération hybride — BM25 lexical fusionné aux vecteurs bge-m3, parce qu’un nom propre arabe ne se retrouve pas par similarité seule.
  • Ingestion incrémentale non destructive — empreintes SHA-256, remplacement par document, orphelins signalés par --status.
  • Mesure avant croyance — jeu d’or versionné, hit@k et MRR, contrôle de fidélité de la réponse au contexte.
  • Python
  • FastAPI
  • ChromaDB
  • Ollama
  • Tailwind RTL
  • Docker
  • pytest

03 · Desktop Rust 2026

SilenceLess

Retire les silences d’un enregistrement de conférence et exporte en MP3 — en flux, avec une mémoire bornée à environ 7 Mo même sur plusieurs heures d’audio.

  • Détection par seuil RMS (dBFS) — fenêtre glissante et pas configurables, marge de silence conservée pour ne pas couper les mots.
  • Traitement en parallèle — plusieurs fichiers à la fois, coupe optionnelle des silences internes, bitrate LAME réglable.
  • Trois interfaces, un algorithme — application Tauri, CLI Rust et prototype Python de référence pour valider les résultats.
  • Parité vérifiée — les tests comparent le rendu en flux au rendu mémoire, pas seulement la sortie.
  • Rust
  • Tauri
  • LAME
  • Cargo workspace
  • Python

04 · Backend Java 2026

ARChecker

API qui reçoit un rapport de conformité Excel, l’aplatit en JSON, l’envoie à un LLM local avec le référentiel du client et renvoie un verdict strictement structuré.

  • Structured Output — .entity(AuditResultDTO.class) via Spring AI : le LLM remplit un contrat, on ne parse pas du texte libre.
  • Extraction exhaustive — tous les onglets, toutes les lignes via Apache POI, avant toute décision.
  • Référentiel par client — rulebook.json injecté dans le prompt, donc une même API sert plusieurs normes qualité.
  • Erreurs normalisées — 400 requête invalide, 404 client inconnu, 502 LLM injoignable, 500 interne. Documenté par Swagger/OpenAPI.
  • Java 21
  • Spring Boot 3.4

05 · Robotique / Vision 2024

DroneApp

Pilotage clavier temps réel d’un Tello, capture d’images et reconstruction d’une carte 2D de la trajectoire à partir de la vitesse et du cap.

Méthode

Quatre étapes, toujours dans cet ordre.

Le code arrive en deuxième position. Avant, il y a la contrainte, et après, la preuve.

  1. 01

    Cadrer la contrainte

    Où vit la donnée, qui la lit, quel volume, quelle tolérance à l’erreur. C’est là que se décide l’architecture — et souvent le refus du cloud.

  2. 02

    Construire le chemin critique

    Une version qui fait le travail de bout en bout, même imparfaite, avant toute optimisation. Puis les cas limites, puis l’interface.

  3. 03

    Mesurer

    Tests, jeu d’or, benchmark. Si je ne sais pas dire combien, je ne sais pas si c’est bon. Les rapports sont versionnés ou reproductibles.

  4. 04

    Documenter les limites

    Ce qui marche, ce qui ne marche pas encore, ce qui dépend d’un modèle externe. Un README honnête vaut mieux qu’une démo flatteuse.

FAQ

Les questions qu’on me pose avant de commencer.

Pourquoi de l’IA locale plutôt que des API ?

Parce que les cas les plus intéressants sont ceux où la donnée ne peut pas sortir : un corpus sous droits, un rapport de conformité client, des enregistrements de conférence. Avec Ollama, le coût marginal est nul et la démonstration tourne chez celui qui l’installe, sans clé API.

Les dépôts sont-ils réutilisables ?

Quatre le sont, avec leur README, leur configuration et leurs tests. SilenceLess est sous licence propriétaire : le dépôt sert de vitrine technique, pas de base de code à réutiliser.

Quel est ton stack principal aujourd’hui ?

Python pour l’IA, FastAPI et les outils ; Java 21 + Spring Boot quand il faut un backend typé et documenté ; Rust + Tauri quand il faut un exécutable léger et rapide. TypeScript et Tailwind pour les interfaces web.

Tu peux reprendre un projet existant ?

Oui. Je commence par lire le code et lancer les tests avant de proposer quoi que ce soit. La première livraison d’une reprise, c’est souvent la commande qui permet de démarrer le projet — et le test qui échoue.
